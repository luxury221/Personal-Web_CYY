研究

我更关心问题本身：正确证据怎样被找到，Agent 怎样在约束下行动，以及我们怎样证明系统真的变好了。

RESEARCH THESIS

可靠的大模型系统，不应该只在最后一行答案上被评价。

我更愿意把系统拆成可以验证的中间过程：候选证据是否召回、跨模态关系是否保留、Agent 状态是否清晰、工具调用是否可复现、新增模块是否在受控实验中带来收益。当前四条研究线正围绕这些中间过程展开。

01 / RETRIEVAL & GROUNDING

Multimodal RAG

当答案分散在文本、表格、图片与跨页关系中时，系统怎样检索并组织一条真正可验证的证据链？

REPRESENTATION结构化证据节点

保留 page / bbox / section / figure / caption / table，而不是把复杂文档压成匿名文本块。

RETRIEVAL

混合召回与图传播

Embedding、BM25、视觉、表格、KG 与 reference routes 共同提供候选，并利用图关系寻找 bridge evidence。

VERIFICATION证据链自修正

不让 reranker 的单一高分替代完整证据；检查模态覆盖、链完整度与回答句子的支持度。

PROOF / MULTIRANK-RAG

在固定 BM25 candidate set 下，FinQA nDCG@5 从 0.678 提升到 0.878（+0.200）；MultiHop-RAG V5 evidence-chain score 为 0.890，gold-node coverage 为 0.730。

CURRENT BOTTLENECK / NEXT

MMLongBench-Doc 的绝对视觉召回仍受第一阶段 candidate retrieval 限制。下一步优先研究视觉优先候选生成、自适应 multimodal routing 与 learned evidence graph，而不是继续堆后处理模块。

02 / PLANNING & CONTROL

Agentic Systems

怎样让 Agent 会计划、会用工具、会记忆，但不会因为自由生成而失去可控性与可解释性？

ORCHESTRATION显式状态与角色边界

把任务拆成职责清晰的角色，用结构化 artifact 交接，而不是让多个 Agent 通过自然语言无限互聊。

MEMORY长期状态而非聊天历史

保存偏好、证据、任务状态与反馈，并区分预测状态与被新证据重新验证后的实证状态。

GUARDRAIL证据 Gate 与确定性规则

关键判断不完全交给模型自由生成：评分维度、证据要求、工具协议与下一动作尽量显式化。

PROOF / KONGMING

六类 Agent 围绕共享 AgentContext / AgentEvent / AgentArtifact 协作；约 500 条岗位保留来源与内容哈希；10+ verify 脚本覆盖评分、成长闭环与完整用户流程。

CURRENT QUESTION / NEXT

下一步更关注不同 Agent 之间的信息损失、错误传播和长期记忆更新条件：哪些状态应交给模型总结，哪些必须由结构化数据和确定性规则维护。

03 / ROBUSTNESS & INTERPRETABILITY

Evaluation & Interpretability

如果输出看起来更好，我们应该用什么证据证明收益来自方法本身，而不是候选集、数据分布或随机性？

ABLATION控制变量的逐层消融

固定 retriever、candidate K 与数据，再逐层加入结构、视觉、GraphRAG、rerank 与 evidence guard，避免比较条件偷偷变化。

ROBUSTNESS不确定性与表征探针

通过线性 probe 与 token 分布不确定性统计分析模型在哪类问题上容易失效，而不是只看 aggregate accuracy。

REPRODUCIBILITY离线、固定与可回归

固定模型、数据、参数与容器，保存基线、失败样本和版本差异，让结果能够重复检查。

PROOF / EVALUATION PRACTICE

MultiRank-RAG 使用 V0–V5 公开消融并保留简单文本任务作为负对照；AIMO 相关工作尝试使用线性 probe 与 14 类不确定性统计理解模型鲁棒性。

WHAT COUNTS AS PROGRESS

不是所有 benchmark 提升都值得继续：我更关注跨数据集是否稳定、简单任务是否被副作用伤害、失败类型是否发生可解释变化，以及收益能否在固定条件下复现。

04 / REALTIME MULTIMODAL INTERACTION

Multimodal Interaction

当语言模型进入语音、视觉、3D 与实时事件环境之后，怎样协调时序、打断、状态与多模态输入，而不是把它们简单拼接在一起？

STREAMING双向语音与打断

WebSocket 维持实时语音链路，系统要在用户插话、自动结束与响应状态之间保持一致。

SPATIAL3D 场景与动作状态

语言输出需要映射到场景、角色与动作，而不是只生成文本或语音。

EVENT FUSION手势与会话事件协同

MediaPipe 手势事件、语音状态和 3D 动作进入同一会话，要求明确事件优先级和状态切换。

PROOF / INTERACTIVE AVATAR

项目实现文本/图片/预设生成 3D 角色、8 点辅助绑骨、Three.js 场景、Qwen 实时语音 WebSocket 与 MediaPipe 手势链路，并保存会话历史、摘要与录屏。

CURRENT QUESTION / NEXT

下一步关注实时多模态状态的一致性：当语音、手势、动作和模型生成同时发生时，怎样减少冲突、延迟与错误事件传播。
